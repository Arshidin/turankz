   - ✅ Статистика рассчитывается только из своих batches

2. **Статистика по batches**:
   - ✅ `farmerStats`: Активные партии, Требуют действия, Подтверждённые
   - ✅ `farmerBatchSummary`: Confirmed, Soft Committed, Forecast
   - ✅ Все данные валидны и соответствуют реальным batches

3. **Activity Feed**:
   - ✅ Показывает только свои batches
   - ✅ Показывает batches, требующие действия
   - ✅ Показывает недавно подтверждённые batches

4. **Farmer Status Banner**:
   - ✅ Показывает grading level (observer, declared_supplier, standard_supplier)
   - ✅ Показывает access level и next action
   - ✅ Данные из `currentFarmer` - корректны

5. **Reliability Premium Card**:
   - ✅ Показывает premium на основе `currentFarmer.grading`
   - ✅ Данные корректны

---

### ⚠️ Потенциальные проблемы

1. **Неэффективный запрос данных**:
   - ❌ `useBatches()` получает ВСЕ batches, потом фильтрует на клиенте
   - ❌ `usePoolRequests()` получает ВСЕ requests, хотя фермеру они не нужны
   - ❌ `useFarmers()` получает ВСЕ farmers, хотя фермеру они не нужны
   - ❌ `useMpks()` получает ВСЕ mpks, хотя фермеру они не нужны

   **Риск**: 
   - Неэффективность (лишние данные)
   - Потенциальная утечка данных, если RLS не работает правильно
   - Лишняя нагрузка на БД

   **Исправление**: Использовать специализированные хуки для фермера.

## 2. Соответствие ролевой модели и бизнес-логике

### ✅ Соответствует требованиям

Согласно `docs/ACCESS_CONTROL.md`, фермер должен видеть:

| Требование | Статус | Комментарий |
|------------|--------|-------------|
| Own profile | ✅ | Показывается через `currentFarmer` |
| Own livestock batches | ✅ | Показывается через `userBatches` |
| Own sales calendar | ✅ | Не в Overview, но доступен |
| Pool invitations (received) | ✅ | Не в Overview, но доступен |
| Aggregated demand signals | ⚠️ | **НЕ ПОКАЗЫВАЕТСЯ в Overview** |
| Other farmers | ✅ | Не показывается |
| MPK identities | ✅ | Не показывается |
| Pool request details | ✅ | Не показывается |
| Individual batch matches | ✅ | Не показывается |
| System-wide data | ✅ | Не показывается |

---

### ❌ НЕ соответствует требованиям

1. **Отсутствует Aggregated Demand Signals**:
   - ❌ Фермер должен видеть агрегированные сигналы спроса (анонимизированные)
   - ❌ В Overview нет компонента `AggregatedDemandCard`
   - ❌ Согласно `FARMER_PERMISSIONS.canView.aggregatedDemand = true`

   **Требование**: Фермер должен видеть агрегированные сигналы спроса для понимания рынка.

## 3. Что можно улучшить, изменить, доработать

### 🔴 КРИТИЧЕСКИЕ УЛУЧШЕНИЯ

#### 1. Добавить Aggregated Demand Signals

**Проблема**: Фермер не видит агрегированные сигналы спроса в Overview.

**Решение**: Добавить компонент `AggregatedDemandCard` в Overview для фермера.

**Код**:
```typescript
{role === 'farmer' && (
  <div className="mb-6">
    <AggregatedDemandCard />
  </div>
)}
```

---

#### 2. Оптимизировать запросы данных

**Проблема**: Фермер получает все данные, потом фильтрует на клиенте.

**Решение**: 
- Использовать специализированные хуки для фермера
- Не загружать `farmers`, `mpks`, `poolRequests` для фермера

**Код**:
```typescript
// Для фермера не нужны все данные
const { data: batches = [] } = useBatches(); // RLS уже фильтрует
// Не загружать farmers, mpks, poolRequests для фермера
const { data: farmers = [] } = role === 'admin' ? useFarmers() : { data: [] };
const { data: mpks = [] } = role === 'admin' ? useMpks() : { data: [] };
const { data: poolRequests = [] } = role === 'admin' || role === 'mpk' ? usePoolRequests() : { data: [] };
```
